# db フォルダ（SEIKA＋のデータベース用SQL）

GitHub の seika-plus の `db` フォルダに置くファイルの決まりです。

## 置いてあるもの

| ファイル | 内容 | 本番で実行するか |
|---|---|---|
| `000_基準_2026-10.sql` | 2026年10月時点の本番データベースの定義をまとめたもの | しない（作り直すときの参考用） |
| `001_` 〜 | 本番で実行したSQL（番号順） | 実行済み |
| `README.md` | この説明 | — |

## 新しいSQLを追加するとき

1. 番号は前のSQLの次の番号にします（例：`011_` の次は `012_`）。
2. ファイル名は「番号_内容.sql」にします（例：`012_〇〇の修正.sql`）。
3. 拡張子は必ず `.sql` にします（`.txt` にしない）。
4. Supabase の SQL エディタで実行し、結果が「OK」になったことを確かめてから、このフォルダに入れます。

## 注意

- 番号の付いたSQLは、すでに本番で実行済みです。同じものを何度実行しても壊れない作りですが、むやみに実行し直さないでください。
- 2026年10月より前の古いSQLはこのフォルダから削除しました。必要になったときは GitHub の履歴（History）から取り出せます。
- 調べるだけのSQL（結果を見るだけで、データを変えないもの）はこのフォルダに入れません。

## 043_QR出庫数の当日訂正.sql の実行手順

1. アプリの差し替えより先に `043_QR出庫数の当日訂正.sql` をSupabase SQLエディタで実行します。
2. 末尾の「出庫訂正RPC」が `OK` と表示されたら成功です。
3. その後、アプリを差し替えます。SQLだけを実行しても、画面に訂正ボタンは表示されません。

## 044_QR出庫数の訂正_実数調整後も可能.sql の実行手順

1. `043_QR出庫数の当日訂正.sql` が実行済みであることを確認します（未実行の場合は先に043を実行します）。
2. `044_QR出庫数の訂正_実数調整後も可能.sql` をSupabase SQLエディタで実行します。アプリの差し替えより先に実行します。
3. 末尾の「出庫訂正RPC_実数調整後も訂正可」が `OK` と表示されたら成功です。
4. 出庫の後に実数調整・場所移動・重量やロット情報の変更があっても訂正できます。出庫数の差の分だけを現在の在庫へ反映します。棚卸し調整・入庫・廃棄が後にある場合は、これまでどおり訂正できません。

1. `019_本社_第2段階.sql`、`022_本社_作業の削除と仕入れ価格表.sql`、`042_本社下処理_作業中の原料追加と使用量保存.sql` が実行済みであることを確認します。

3. 末尾の5行がすべて `OK` と表示されたら成功です。

必要です。下処理の訂正・休憩の記録・同時製造の内訳を安全に保存する表と関数を追加します。

## 046_本社下処理_日報後入力と歩留まり.sql の実行手順

1. `019_本社_第2段階.sql`、`022_本社_作業の削除と仕入れ価格表.sql`、`023_本社_使用期限とトレース表.sql`、`042_本社下処理_作業中の原料追加と使用量保存.sql`、`045_本社下処理_訂正と休憩と同時製造.sql` が実行済みであることを確認します。

### 実行する順番

### 成功したかどうかの確かめ方
