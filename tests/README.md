# SEIKA＋の自動チェック

## まとめて実行する

リポジトリ直下で次を実行します。

```bash
python3 tests/run_all.py
```

共通入口がこのリポジトリ用の一時HTTPサーバーを起動し、次を順に実行します。

1. `tests/smoke.py`：架空データで既存の主な画面を確認
2. `tests/permissions.py`：全11役割の権限を確認
3. `tests/sync.py`：擬似サーバーで保存・同期の11パターンを確認
4. `tests/test_*.py`：Python標準の `unittest` で追加テストを名前順に確認

1本でも失敗・起動失敗・実行上限超過があれば、全体を失敗として返します。1本が失敗しても残りのテストは実行します。
共通入口は `SEIKA_URL` の設定を引き継がず、自分で起動した `127.0.0.1` のURLを子テストへ渡します。
既存画面・権限テストのSupabase通信は遮断し、保存・同期テストのSupabase通信は擬似応答へ置き換えます。本番DBへ保存しません。
テスト1本の実行上限は480秒です。GitHubの自動チェック全体は、現在の設定で15分の上限があります。

準備は既存の `.github/workflows/smoke.yml` と同じです。Python、Node、PlaywrightとそのChromiumが必要です。
この変更では新しい外部ライブラリを追加しません。

### このテストで保証しない点・別途修正が必要な点

追加診断で、1・2は仮ブラウザ、3は実ソースと仮の依存処理を使って以下を再現しました。安全な挙動が確認できたテストとは区別し、今回のアプリ修正や合格条件には含めていません。

1. **単価再送中に新たに追加された単価データの保持**：開始時点のキューを使って最後に保存し直すため、再送中に追加した別の単価データが最後に端末キューから消えました。
2. **単価だけの同時再送防止**：再送を同時に2回呼び出すと、同じ単価データが2回送信されました。通常再送の実行中フラグを、単価再送全体の保護とみなすことはできません。
3. **端末書込みの失敗を後続の単価再送へ引き継ぐこと**：標準データのキューが空で端末書込みが失敗すると、標準再送がエラーを内部で受け止め、最終入口は未同期件数だけを確認して単価再送へ進む場合があります。待機が正常に完了する場合の順番確認とは別です。

上記の修正は待ち方・キューの更新方法に関わるため、今回のテスト追加に混ぜません。本番での発生状況は未確認です。通信復帰時に単価だけを自動再送することも、この変更の確認範囲に含めません。
