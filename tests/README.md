# SEIKA＋の自動チェック

## まとめて実行する

リポジトリ直下で次を実行します。

```bash
python3 tests/run_all.py
```

共通入口がこのリポジトリ用の一時HTTPサーバーを起動し、次を順に実行します。

1. `tests/smoke.py`：架空データで既存の主な画面を確認
2. `tests/permissions.py`：全11役割の権限を確認
3. `tests/sync.py`：擬似サーバーで保存・同期の11パターンを確認
4. `tests/test_*.py`：Python標準の `unittest` で追加テストを名前順に確認

1本でも失敗・起動失敗・実行上限超過があれば、全体を失敗として返します。1本が失敗しても残りのテストは実行します。
共通入口は `SEIKA_URL` の設定を引き継がず、自分で起動した `127.0.0.1` のURLを子テストへ渡します。
既存画面・権限テストのSupabase通信は遮断し、保存・同期テストのSupabase通信は擬似応答へ置き換えます。本番DBへ保存しません。
テスト1本の実行上限は480秒です。GitHubの自動チェック全体は、現在の設定で15分の上限があります。

準備は既存の `.github/workflows/smoke.yml` と同じです。Python、Node、PlaywrightとそのChromiumが必要です。
この変更では新しい外部ライブラリを追加しません。

## 今回だけ行うGitHub画面の設定変更

Workflows権限は追加しません。設定ファイルは平田さんがGitHub画面で編集します。

**PR #40はmainへ反映済みです。PR #41は別の作業ブランチへマージされたため、mainには入っていません。今回のmain宛て復旧PRで、保存・同期テストと共通入口を反映します。**

1. 今回のmain宛て復旧PRをマージする。追加SQLは不要です。PR #40のSQLを再実行する必要もありません。
2. GitHubで `main` の `.github/workflows/smoke.yml` を開き、鉛筆の編集ボタンを押す。
3. 最後の次の1行だけを変更する。前の空白はそのまま残す。

変更前：

```yaml
          python3 tests/smoke.py
```

変更後：

```yaml
          python3 tests/run_all.py
```

4. **Commit changes** で `main` に保存する。ほかの行は変えない。
5. GitHubの **Actions → 自動チェック** で、この設定変更後の実行が成功したことを確認する。ログには `smoke.py`、`permissions.py`、`sync.py`、`test_run_all.py`、`test_hq_direct.py` と最後に「自動チェック: すべてOK（5本）」が出る。

`run_all.py` が入る前に設定だけを変更すると、ファイルが見つからず失敗するため、必ずこの順番で行います。
設定変更前の緑のチェックは、従来の `smoke.py` だけの結果です。追加テストまで合格した証拠にはなりません。
既存設定が起動する8765番のHTTPサーバーはそのままでも構いません。共通入口は別の空きポートを使います。

## 今後のテスト追加

- `tests/test_内容.py` という名前で `unittest.TestCase` のテストを追加します。共通入口が自動的に検出します。
- 補助ファイルは `test_` で始めない名前にします。`tests/` 直下の通常ファイルだけを対象にします。
- `unittest` のテストが0件なら失敗します。単に `def test_...` を書くだけのpytest形式や、単独スクリプト形式では実行できません。
- 既存3本は削除・改名しません。どれかが無い場合も失敗として検出します。
- テストから `run_all.py` を再び起動しません。共通入口の自己テストはimportして確認します。
- 新しいブラウザテストでは、本番URLを使わず、外部通信を遮断するか架空の応答へ置き換えます。

通常のテスト追加・修正はPRのマージだけで反映され、設定ファイルの追記は不要です。
実行環境、必要なライブラリ、実行タイミング、ジョブ構成や全体の実行上限を変更するときは、自動チェック設定の編集が再び必要になります。

## 確認範囲

- 仮のデータで確認：この共通入口と、既存画面・権限・保存同期のテスト。
- 本番で確認：別途必要。本番データ、実機印刷、通信障害時の実機動作まではこのテストでは保証しません。
